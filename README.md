# 自動車報道ウォッチ

自動車業界の情報を3つの面から一画面で追う個人用ダッシュボードです。

| タブ | 中身 |
| --- | --- |
| **報道** | 新聞社・通信社・テレビ局が報じた自動車関連の見出し |
| **企業リリース** | 各社が自社サイトに出したお知らせ（報道されない小さな告知を含む） |
| **ネットの反響** | はてなブックマークで集まっている記事と、Googleトレンドの急上昇 |

追跡企業は**87社**（日産部品販売会社は全国24法人を1社として扱います）。見出しに出ている記事には企業名の印が付きます。

見出しとリンクのみを扱い、記事本文は取得も保存もしません。

---

## 企業を増やすときに触るのは1ファイルだけ

**`lib/companies.ts`** がこのアプリの起点です。ここに1社足すと、

- 見出しへの企業タグ付け
- Google ニュースの企業別クエリ（`gnews: true` のとき）
- はてなブックマークの反響取得（`buzz: true` のとき）
- 自社ニュースリリースの取得（`newsUrl` があるとき）
- 本国ニュースルームの取得（`globalNewsUrl` があるとき）

が**まとめて増えます**。取得元を別ファイルに書き足す必要はありません。

```ts
{
  code: "7261",
  short: "マツダ",
  name: "マツダ",
  sector: "oem",
  aliases: ["マツダ", "MAZDA"],
  newsUrl: "https://newsroom.mazda.com/ja/publicity/release/",
  gnews: true,
  buzzQuery: "マツダ 自動車",
},
```

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| `code` | ○ | 証券コード。非上場なら `mazda` のような文字列でも可 |
| `short` | ○ | 画面のタグに出る短い名前。5〜6文字までが読みやすい |
| `name` | ○ | 正式名称。企業セレクトに出る |
| `sector` | ○ | `oem` / `dealer` / `finance` / `parts` / `other` |
| `aliases` | ○ | 見出しに現れる表記のゆれ。**ここが精度を決める** |
| `newsUrl` | | 自社お知らせ一覧のURL。省略すると企業リリースは取得しない |
| `newsKind` | | `rss` か `html`。省略時は `html` |
| `extraNewsUrls` | | 地域別法人など、1社が複数のお知らせページを持つ場合の追加URL。タグは1つにまとまる |
| `globalNewsUrl` | | 本国・グループ本体のニュースルーム（海外メーカー用） |
| `gnews` | | Google ニュースで個別クエリを回すか。報道量の多い社だけ |
| `buzz` | | はてなブックマークで反響を追うか。話題になりうる社だけ |
| `buzzQuery` | | はてブの検索語。省略時は `name` を使う |
| `note` | | 取得できない理由などのメモ。画面には出ない |

`newsUrl` と `globalNewsUrl` に `{year}` と書くと、取得時に現在の年（JST）へ
置き換わります。年別ページしか静的に読めないサイト（日野自動車など）のための
仕組みです。

### aliases の書き方

大文字小文字と全角半角は自動で吸収されます。書き分けが必要なのは
**カタカナ・英字・ブランド名・略称**です。

```ts
aliases: ["三菱自動車", "三菱自", "MITSUBISHI MOTORS"]
```

`"三菱"` だけにすると三菱商事や三菱UFJの記事まで拾ってしまいます。
グループ名だけの企業は、業種を表す語と組み合わせた `buzzQuery` を
指定すると精度が上がります。

### `gnews` と `buzz` を付ける基準

全社に付けると取得元が増えすぎて更新が遅くなります。現在の内訳は、

| | 社数 |
| --- | --- |
| 登録企業 | 87 |
| 企業リリースを取得（`newsUrl`） | 60 |
| 本国ニュースルーム（`globalNewsUrl`） | 7 |
| Google ニュース個別クエリ（`gnews`） | 35 |
| はてブ反響（`buzz`） | 28 |

取得元は合計169件です（日産部品販売会社は地域16法人ぶんを1社にまとめています）。日々報道される規模の企業だけに `gnews` を付け、
ネットで話題になりうる企業だけに `buzz` を付けてください。部品メーカーの
大半は、横断クエリと企業リリースで十分です。

### 企業リリースの `newsUrl`

**お知らせの一覧ページ**を指定します（個別記事やトップページではなく）。
抽出は「日付 + 見出しリンク」の並びを探す汎用の仕組みなので、社ごとに
コードを書く必要はありません。日本の企業サイトはほぼこの形です。

うまく取れない場合は、画面下部の「取得元の状態」でその行が0件になります。
よくある原因は、

- ページがJavaScriptで描画されている（この方式では取れません）
- 指定したURLが一覧ページではない
- 日付が画像になっている

どれも `newsUrl` を消せば、その社は報道と反響だけになります。

## セットアップ

必要なもの: Node.js 18.18 以上

```bash
npm install
npm run dev     # http://localhost:3000
```

## Vercel へのデプロイ

1. このディレクトリをGitHubのリポジトリにpush
2. https://vercel.com で「Add New… → Project」からそのリポジトリを選ぶ
3. 設定は変更不要。「Deploy」

以降、GitHub上でファイルを編集して Commit すれば自動で再デプロイされます。

| 環境変数 | 既定値 | 意味 |
| --- | --- | --- |
| `NEWS_CACHE_SECONDS` | `120` | サーバー側でフィードを再取得しない秒数 |
| `FEED_TIMEOUT_MS` | `8000` | 1フィードあたりの取得タイムアウト |

### 取得元が150を超えるための工夫

取得元が多いので、1回のリクエストで全部を取りには行きません。

1. **タブごとに分けて取得** します（`/api/news?section=report` など）。開いている
   タブだけを読み、残りは1.5秒後に裏で先読みします。
2. **Next.js のデータキャッシュ**に預けます。タブごとの再取得間隔は、報道5分・
   企業リリース30分・反響15分です。2回目以降は外部へ出ずに返ります。
3. 同時取得は10件ずつに区切り、配信元へ殺到させません。

画面は1分ごとに表示中のタブを再取得しますが、キャッシュが効いていれば外部への
アクセスは発生しません。「今すぐ更新」はキャッシュを無視して取り直します。

再取得間隔は `app/api/news/route.ts` の `REVALIDATE`、同時取得数は環境変数
`FEED_CONCURRENCY` で変えられます。

## 取得元について

### 報道

新聞社・通信社・テレビ局の多くは自社RSSを廃止しているか、配信URLを公開して
いません。そこで**Google ニュースの検索RSS**を主軸にしています。

```
https://news.google.com/rss/search?q=<クエリ>&hl=ja&gl=JP&ceid=JP:ja
```

配信元の媒体名が返るので、`site:nikkei.com` と書けば媒体を指定できます。
`lib/sources.ts` に通信社4・新聞社7・テレビ局6の媒体別クエリを定義しています。

媒体を足すのは1行です。

```ts
gn("nishinippon", "西日本新聞", "press", `${AUTO} site:nishinippon.co.jp when:5d`),
```

`when:` は対象期間。記事の多い媒体は `2d`、少ない媒体は `7d` が目安です。

### ネットの反響

**はてなブックマーク**の検索RSSを企業ごとに叩き、ブックマーク数を反響の
強さとして表示します。`users=3` で3ブックマーク以上に絞っています。この
しきい値は `lib/sources.ts` の `BUZZ` で変えられます。

**Googleトレンド**の急上昇ワードのうち、追跡企業に当たったものだけを残します。

### X（旧Twitter）について

**現状このアプリはXを見ていません。** 理由は費用です。

X APIは2026年4月から従量課金制になり、月額契約は不要になりましたが、
投稿の読み取りが**1件あたり $0.005** です。常時監視すると月数百ドル規模に
なります。1日数回・各50件程度に抑えれば月$10〜30程度で、使えなくはありません。

足す場合は `lib/sources.ts` に `kind: "x"` の取得元を追加し、
`app/api/news/route.ts` の `parseBySource()` に分岐を足す形になります。
APIキーは環境変数に置いてください。

## 動かないときは

画面下部の**「取得元の状態」**を最初に見てください。タブごとに、フィード単位の
取得件数とエラーが出ます。

| 症状 | 原因と対処 |
| --- | --- |
| 全部が赤い | サーバーから外部へ出られていない。Vercelなら再デプロイ、ローカルならプロキシ設定を確認 |
| 特定の媒体だけ0件 | その媒体が該当期間に自動車記事を出していない。`when:` を伸ばす |
| 企業リリースが0件 | `newsUrl` が一覧ページを指していないか、JSで描画されている |
| 企業リリースに変なリンクが混ざる | ナビゲーションを拾っている。`lib/html.ts` の `NOISE` に語を足す |
| 「要確認」の行が赤い | 推定URLが外れている。その行を消すか正しいURLに直す |
| `HTTP 429` | 取得しすぎ。`NEWS_CACHE_SECONDS` を増やす |
| 更新が遅い | 取得元が増えすぎ。`gnews: true` を減らすか `CONCURRENCY` を調整 |

## 構成

```
app/
  layout.tsx          フォント読み込みとメタデータ
  page.tsx            エントリポイント
  globals.css         配色・タイポグラフィ（ライト/ダーク両対応）
  api/news/route.ts   全取得元を並列取得し、正規化して返すAPI
lib/
  companies.ts        追跡企業の定義 ← 企業を増やすときはここだけ
  sources.ts          取得元の生成（媒体を増やすときはここ）
  keywords.ts         業界キーワード・自動車判定
  rss.ts              RSS/Atom・はてブ・トレンドの解析、重複排除
  html.ts             企業サイトのお知らせ欄からの汎用抽出
  types.ts            型定義
components/
  Portal.tsx          画面本体（タブ・フィルタ・自動更新・取得元の状態）
```

## 制約

- **Google ニュースのリンクは転送ページ経由**です。元記事に直行させたい媒体は
  自社RSSを直接読む設定に変えてください。
- **速報性はGoogle ニュースの反映速度に依存します。** 媒体が記事を出してから
  RSSに載るまで数分〜数十分かかることがあります。
- **`site:` 指定は完全ではありません。** Google ニュースの索引に載っていない
  記事は拾えません。
- **企業リリースの抽出は汎用の推定**です。取りこぼしも、稀に無関係なリンクの
  混入もあります。
